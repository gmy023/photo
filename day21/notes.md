# 第 21 天：修 bug + 重构记录

日期：2026-11-08
产出：`day21/app.html`（衣橱 + 天气合并版）

## 一、合并时踩的坑

**1. id 撞车（合并第一步就遇到）**

- 现象：把两块代码放进同一个页面后，点天气的「查询」没反应，点衣橱的「按价格排序」反而把游戏重开了一局。
- 原因：两个页面都有自己的 `#btn`、`#list`、`#msg`，`getElementById` 只返回文档里第一个匹配的元素，后面的同名 id 全被忽略。
- 修法：合并前先给 id 加前缀，衣橱统一 `wd-`（`wd-grid`、`wd-form`、`wd-price`…），天气统一 `wt-`（`wt-city`、`wt-btn`、`wt-result`），再用 `querySelectorAll("#wd-filters .chip")` 这类带前缀的选择器取元素，两块的 id 不会再互相干扰。

## 二、按找茬清单测出来并修掉的 bug

**2. 连续添加两件同名衣服，删一件却消失两件**

- 现象：快速连点两次「加入衣橱」加了两件同名衣服，再点任意一件的「删除」，两件一起消失。
- 原因：新增时用 `id: Date.now()` 当唯一标识，两次点击落在同一毫秒里就会拿到**相同 id**；删除时 `filter` 按 id 比对，两条一模一样的数据被一起过滤掉。
- 修法：抽出 `nextId(list)`，取现有最大 id 加 1（`return max + 1`），id 从此只增不重；删除仍然只比对 id，但一条数据只会命中一次。

**3. 「按价格排序」把顺序永久写进了 localStorage**

- 现象：点一次排序后，刷新页面顺序还是排好的；再点季节筛选，列表也依然是上次排序的顺序，想恢复原始顺序只能清缓存。
- 原因：`loadData().sort(...)` 之后又调了 `saveData(...)`，把「当前视图的排序」当成了「数据本身」存起来。排序是看的方式，不是数据。
- 修法：排序改成视图状态，用 `sortAsc` 记录（`null` 不排 → `true` 低到高 → `false` 高到低，按钮文案跟着变「价格 ↑ / 价格 ↓」），只在 `getVisibleList()` 里对数组副本排序，不再写回存储。

**4. 衣橱为空时点「清空」没有反馈**

- 现象：全部删完后再点「清空」，页面什么都不提示，用户以为按钮坏了。
- 原因：原版本根本没有清空功能，删到 0 件时列表只剩一行空态文案，没有任何「已经是空的」的出口。
- 修法：新增 `clearWardrobe()`，进来先判断 `loadData().length === 0`，是空的就 `showToast("衣橱已经是空的啦", true)` 直接返回，不做无意义的写存储；非空才 `saveData([])` 并提示「衣橱已清空」。

**5. 价格输入 `0`、`-5`、`abc` 的提示文案误导**

- 现象：价格填 `abc`（number 输入框里读出来是空字符串）时，弹的是「请填写名称、颜色和大于 0 的价格」，用户会以为是自己名字没填。
- 原因：名称、颜色、价格三个字段挤在同一个 `if` 里，一条提示兜底所有情况，`Number("")` 得到 0 又被 `!(price > 0)` 顺手拦住，看起来"拦住了"但说不清哪里错。
- 修法：拆成两段校验——先 `if (!name || !color)` 提示名称颜色必填，再 `if (!Number.isFinite(price) || price <= 0)` 提示价格必须是大于 0 的数字，错在哪就说哪。

**6. 天气查询快速连点两次会重复发请求**

- 现象：手快连点「查询」，两组请求同时在跑，先发的后返回，结果区先闪一下旧城市再被覆盖；按钮文字也会卡在「查询中…」。
- 原因：按钮的 `disabled` 要等渲染线程处理完才生效，光靠它挡不住同一轮里的第二次点击；而且没有其他地方记录"正在查"这个状态。
- 修法：加 `isLoading` 标记，`query()` 进来第一行 `if (isLoading) return;`，发请求前置 `true`，`finally` 里再置回 `false`，和按钮的禁用、文案恢复一起收尾，无论成功失败都能恢复。

## 三、重构（让代码少复制粘贴）

1. 常量提到脚本顶部：`KEY`（localStorage 键名）、`DEFAULT_WARDROBE`（10 件初始数据）、`COLOR_HEX`（颜色 → 色值映射）、`WEATHER_TEXT`（天气代码 → 中文），改数据只改一处。
2. 渲染只留一个入口：原来"筛选季节 + 搜索 + 排序 + 渲染 + 统计"散在四个事件里，现在拆成 `getVisibleList()`（只管算要显示哪些）和 `renderList()`（只管画和统计），四个事件都只调 `renderList()`。
3. 空态和统计合并到 `renderList()` 里，先算统计再判断空列表，不会再出现"统计没更新但列表空了"的不一致。
4. 天气部分抽出 `weatherToText()`、`tipByTemp()`、`showLoading()`、`showError()`、`showWeather()`，`getWeather()` 只负责发请求和抛错，事件处理只负责调度，出问题一眼能定位在哪一层。
